# Website

spinclip.bandpassrecords.com, built with [Astro](https://astro.build). `.github/workflows/site.yml` builds it and commits the result to the `gh-pages` branch, which GitHub Pages serves. Each published version is a commit there: to go back, revert it on `gh-pages`. Never edit `gh-pages` by hand — the next publish replaces it with what `website/` builds.

```bash
cd website
npm install
npm run dev       # http://localhost:4321, reloads as you edit
npm run build     # dist/
npm run preview   # serves dist/
```

## Where things come from

| On the page | Source |
|---|---|
| App screenshots | `../resources/screenshots/` — taken from the real app by `../scripts/capture_screenshots.ps1` |
| Example stills and clips | `../resources/examples/` — rendered through the app's own pipeline by the same script |
| Both of the above, as served | copied into `public/resources/` by `scripts/sync-resources.mjs` before `dev` and `build`; never edit the copies |
| Download links | the newest GitHub release, read at build time (`src/lib/release.ts`); the release workflow rebuilds the site after publishing |
| What's new (`/changelog/`) and the version on the homepage | `../CHANGELOG.md`, read at build time (`src/lib/changelog.ts`) |
| `CNAME` | `public/` — the domain |
| `.nojekyll` | `public/` — without it Pages runs Jekyll, which drops Astro's `_astro/` folder (every script and stylesheet) |
| The user guide | `src/content/docs/guide/` — one page per section, served by [Starlight](https://starlight.astro.build) at `/guide/` with search; the sidebar is `src/data/guide-sidebar.json` |
| Colours | `src/styles/site.css` (homepage) and `src/styles/starlight.css` (guide): the app icon's orange on warm near-black |

## Retaking the pictures

When the UI or the look of a render changes, run `scripts/capture_screenshots.ps1` from the repo's root (Windows) and commit what changes under `resources/`. The demo artwork and songs are generated by `tool/demo_media/make_demo_media.dart`, so nothing on the site is someone else's work.
